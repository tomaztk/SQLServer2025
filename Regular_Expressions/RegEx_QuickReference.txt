THE 7 REGEXP FUNCTIONS
=======================
1. REGEXP_LIKE(str, pattern [, flags])        -> Boolean (1/0)
2. REGEXP_INSTR(str, pattern [, pos [, occ]]) -> Position (1-based)
3. REGEXP_SUBSTR(str, pattern [, pos [, occ]]) -> Extracted text
4. REGEXP_REPLACE(str, pattern, repl)         -> Modified string
5. REGEXP_COUNT(str, pattern)                 -> Match count
6. REGEXP_SPLIT_STR(str, pattern)             -> Table-valued
7. Capturing Groups with (group) in pattern   -> Group extraction

PERFORMANCE RANKING (Fastest -> Slowest)
========================================
★★★★★  REGEXP_LIKE()      (filter, validate)
★★★★   REGEXP_INSTR()     (find position)
★★★    REGEXP_SUBSTR()    (extract)
★★★    REGEXP_COUNT()     (count matches)
★★     REGEXP_REPLACE()   (transform - allocation cost)
★      REGEXP_SPLIT_STR() (split - result set cost)

COMMON VALIDATION PATTERNS
===========================

Email:
^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$

Phone (US):
^\+?1?[-.\s]?\(?[0-9]{3}\)?[-.\s]?[0-9]{3}[-.\s]?[0-9]{4}$

IPv4 Address:
^(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)$

URL:
^https?://[-a-zA-Z0-9@:%._+~#=]{1,256}\.[a-zA-Z0-9()]{1,6}\b[-a-zA-Z0-9()@:%_+.~#?&/=]*$

Date (YYYY-MM-DD):
^[0-9]{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12][0-9]|3[01])$

Hex Color (#RRGGBB):
^#[0-9A-Fa-f]{6}$

US Zip Code:
^\d{5}(?:-\d{4})?$

Credit Card (4 groups of 4 digits):
^[0-9]{4}[-\s]?[0-9]{4}[-\s]?[0-9]{4}[-\s]?[0-9]{4}$

QUICK EXAMPLES
==============

-- Validate email
SELECT REGEXP_LIKE('john@example.com', '^[^@]+@[^@]+\.[a-z]+$')
-> Returns: 1 (TRUE)

-- Extract phone digits only
SELECT REGEXP_REPLACE('(555) 123-4567', '[^\d]', '')
-> Returns: '5551234567'

-- Mask credit card
SELECT REGEXP_REPLACE(CardNo, '^.{12}', 'XXXXXXXXXXXX')
-> Returns: 'XXXXXXXXXXXX3456'

-- Count words in text
SELECT REGEXP_COUNT('The quick brown fox', '\w+')
-> Returns: 4

-- Extract domain from email
SELECT REGEXP_SUBSTR('user@example.com', '@(.+)$', 1, 1, 'c', 1)
-> Returns: 'example.com'

-- Split comma-separated values
SELECT value FROM REGEXP_SPLIT_STR('apple,banana,orange', ',')
-> Returns: apple, banana, orange (3 rows)

-- Check if password has uppercase
SELECT REGEXP_COUNT('MyPassword123', '[A-Z]') >= 2
-> Returns: 1 (TRUE)

DANGEROUS PATTERNS (CATASTROPHIC BACKTRACKING)
==============================================
NOK (a+)+b              Nested quantifiers - TIMEOUT
NOK (a|a)+b             Overlapping alternation - EXPONENTIAL
NOK (.*)*b              Nested .* - EXPONENTIAL
NOK (a|ab)+b            Ambiguous chains - EXPONENTIAL
NOK (a*)*b              Repeated quantifiers - EXPONENTIAL

OK Instead use:
OK a+b                  Direct quantifier
OK a{2,10}b             Bounded quantifier
OK (a|b)+               Clear alternation

DO's & DON'Ts
=============
DO: Test patterns with sample data first
DO: Use REGEXP_LIKE for filtering (fastest)
DO: Create indexed computed columns for common patterns
DO: Handle NULL with ISNULL()
DO: Escape special characters: \. \$ \( \)
DO: Use 'i' flag only when needed (slower)
DO: Pre-filter with simple WHERE before REGEXP_REPLACE

DON'T: Use nested quantifiers (a+)+
DON'T: Construct patterns from user input
DON'T: Assume REGEXP is always faster than LIKE
DON'T: Apply expensive operations to unindexed columns
DON'T: Forget NULL values in your data
DON'T: Test only with small sample data

PERFORMANCE TIPS
================
1. Use REGEXP_LIKE for WHERE clauses (returns immediately on match)
2. Create persisted computed columns for frequently checked patterns
3. Index the computed columns with CREATE NONCLUSTERED INDEX
4. Pre-filter with LIKE or CHARINDEX before expensive REGEXP_REPLACE
5. For simple patterns (literals, single char classes), LIKE might be faster
6. For complex patterns (alternation, groups), REGEXP is comparable or faster
7. Batch process instead of processing all rows at once
8. Monitor execution time with SET STATISTICS TIME ON
9. Consider Full-Text Search for very large text columns (>1MB)
10. Test performance on production-size data before deployment

SYNTAX QUICK REFERENCE
======================

-- Boolean match
REGEXP_LIKE(column, 'pattern')

-- Find position
REGEXP_INSTR(column, 'pattern')

-- Extract text
REGEXP_SUBSTR(column, 'pattern')

-- Extract with groups
REGEXP_SUBSTR(column, '(group1)(group2)', 1, 1, 'c', 1)  -> group 1
REGEXP_SUBSTR(column, '(group1)(group2)', 1, 1, 'c', 2)  -> group 2

-- Replace
REGEXP_REPLACE(column, 'pattern', 'replacement')

-- Count
REGEXP_COUNT(column, 'pattern')

-- Split
SELECT value FROM REGEXP_SPLIT_STR(column, 'delimiter_pattern')

-- Create indexed computed column
ALTER TABLE table ADD
  IsValid AS REGEXP_LIKE(column, 'pattern') PERSISTED

CREATE NONCLUSTERED INDEX IX_IsValid ON table(IsValid)

COMMON USE CASES
================
Data Validation      -> REGEXP_LIKE in computed column + index
Data Extraction      -> REGEXP_SUBSTR with capturing groups
Data Masking/PII     -> REGEXP_REPLACE on SELECT (not UPDATE usually)
Log File Parsing     -> REGEXP_SUBSTR with multiple extractions
Data Quality Checks  -> REGEXP_COUNT for validation rules
Tokenization         -> REGEXP_SPLIT_STR on delimiters
Format Normalization -> REGEXP_REPLACE to standardize format

INLINE REGEX FLAG
=================
'i' = Case-insensitive
Example: REGEXP_LIKE('Hello', 'hello', 'i')  -> Returns 1

ENGINE SELECTION (Automatic)
=============================
Simple pattern -> DFA optimization (fastest)
Complex pattern -> NFA with optimization
Very complex -> Full NFA mode

Result: You don't choose, SQL Server picks optimal engine automatically!
